## What's in the database

All of it is in `supabase/migrations/`, applied in order:

| Migration | What |
| --- | --- |
| `…_init_schema.sql` | Tables, leaderboard views, row level security, privileges, realtime |
| `…_functions.sql` | Server-side logic (below) and the login trigger |
| `…_seed_data.sql` | Time rates, the 12 goals, 8 wheel prizes, 128 challenges. Generated by `scripts/gen-seed.py` |
| `…_fk_indexes.sql` | Two indexes the performance advisor asked for |
| `…_prize_win_label.sql` | Short prize phrases for the "Ultimele premii" list |

Tables: `timer`, `stats`, `rates`, `events`, `goals`, `viewers`, `watch_time`,
`prizes`, `spins`, `challenges`, `vote_rounds`, `round_challenges`, `votes`,
`suggestions`. Views: `leaderboard_gifts`, `leaderboard_bits`, `leaderboard_hours`.

**Who can do what**

- Visitors (logged out) can **read** public data: timer, stats, events, goals,
  rates, prizes, recent spins, challenges, rounds and tallies, watch-time
  leaderboard. They can't write anything.
- Logged-in viewers can also read their own viewer row, votes and suggestions,
  and call four functions: `cast_vote`, `suggest`, `spin`, `wheel_status`.
  Each checks who's calling (and, for votes and suggestions, that they're
  subscribed).
- Everything else (adding time, starting the timer, crediting watch time) is
  backend-only: Edge Functions with the service role, or the SQL editor.

## Testing the live site without Twitch

From the SQL editor (or the Supabase connector) you can drive the page by hand:

```sql
select public.start_timer(3*86400, now() + interval '4 days');           -- go live
select public.record_event('twitch','sub','t1','1','test','test','3000'); -- a Tier 3 sub
select public.record_event('twitch','gift','t2','2','test2','test2','1000', 10);
```

Open https://icemaraton.icemaraton.workers.dev/ and it updates within a second. Reset afterwards:
delete from `spins`, `vote_rounds`, `events`; zero `stats`; set `timer` back to
`upcoming` with null times; clear `goals.unlocked_at`.

## How the page gets its data (since 24 Nov 2026)

- **One call:** `public_state(versions)`. The public data is split into parts
  (timer, stats, feed, boards, goals, vote, prizes, wins, bingo). Each part is
  computed once when its tables change (statement triggers →
  `private.refresh_parts`) and cached with a version in `private.state_parts`.
  The page sends the versions it has and gets back only what changed.
- **Polling:** every 8 seconds while the tab is visible (the OBS overlay every
  3 s), never in hidden tabs. When it fails it backs off up to 2 minutes with
  jitter, and it checks again at once on return or reconnect. A cron job
  (`icemaraton-state`) re-checks the time-based parts every minute.
- **Per viewer:** `my_state(round)` returns everything about the logged-in
  viewer in one call.
- **Overlay:** `feed_since(id)` returns every event after the last one shown,
  so bursts are queued in full.
- **Leaderboards** come from `private.supporter_totals`, kept by a trigger on
  `events`, not from sums over the whole table.
- **Names:** everything public goes through `public_name(login, name)`:
  - viewer opt-out (`set_public_name`, button under the leaderboard);
  - moderator hide or allow (`mod_name_rule`, /mod → Nume);
  - a word, link and phone filter (`private.blocked_words`, mode `any`, `prefix`
    or `exact`). To add a word:
    `insert into private.blocked_words (word, mode) values ('cuvant', 'exact');`
- **Sponsor tracking:** `track_sponsor` counts once per visitor (a salted daily
  hash of the IP), sponsor, kind and day, and only known sponsors
  (`private.known_sponsors` plus any sponsor named in the data).
- **Health:** `mod_health()` feeds the "Sănătate" card on /mod.

**After deploying the new site, run `supabase/after-deploy/lockdown_public_reads.sql`.**
It removes direct public reads of `events` and `watch_time`.

## Edge Functions (deployed)

Source in `supabase/functions/`, shared Twitch helpers in `_shared/twitch.ts`.
All are deployed with `verify_jwt = false` and authenticate themselves.

| Function | Called by | Does |
| --- | --- | --- |
| `twitch-eventsub` | Twitch EventSub webhooks | Verifies the HMAC signature, records subs/resubs/gifts/bits via `record_event`, sets stream online/offline |
| `twitch-auth` | Iceman, via the button on `/mod` | Twitch OAuth for the broadcaster, stores the token in Vault, (re)creates the six EventSub subscriptions |
| `check-sub` | The site, after login and "M-am abonat, verifică iar" | Checks the viewer's sub with the broadcaster token, updates `viewers.is_subscriber` |
| `watch-time` | pg_cron every 5 min (`x-cron-secret`) | Chatters list + sub status → `credit_watch_time` (only while live and online) |
| `tipeee-donations` | pg_cron every 15 s (`x-cron-secret`) | New TipeeeStream donations (euros) → `record_event('donation', …)`, deduped on `tipeee:<id>`; counts only while live; state in `private.tipeee_state` |

Edge Function secrets to set once: `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`.
Generated in Vault by the migrations: `eventsub_secret`, `cron_secret`; later
`twitch_broadcaster_token`.

Scheduled jobs (pg_cron): `icemaraton-minute` (closes finished vote rounds,
ends the timer at zero), `icemaraton-watch-time` (every 5 minutes) and
`icemaraton-tipeee` (every 15 seconds).

Moderator functions (`mod_*`, used by `/mod`) check `viewers.is_moderator`.
Logins in `private.settings.moderator_logins` (initially `icemanlucky`) become
moderators on first login.
